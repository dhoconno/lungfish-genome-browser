# Reader report: Oxford Nanopore Runs

Reader 4. Undergraduate who used Geneious in one class for a course project. Never opened a terminal.

| Location | What stopped me | What would have helped |
| --- | --- | --- |
| What it is, "MinKNOW turns the raw electrical..." | I do not know what a pore is here. In my genetics class sequencing was always pictures of colored dots, so an electrical signal from a pore is a machine I have no picture of. | One sentence saying a pore is a protein hole in a membrane that DNA threads through, and the current change as it passes is what gets read. |
| What it is, "holding the reads that cleared its..." | Its own quality threshold means what number? And is there a failed folder I am supposed to care about? The chapter never mentions one, so I did not know whether I was throwing data away. | Say what the pass threshold usually is and state plainly whether LGE ever looks at the failed reads. |
| What it is, "MinKNOW puts each barcode's reads in..." | I could not tell whether `barcode01` is a name I must use or just an example. The Settings section later says names come from folder names, so it seems literal, but I had to read twice. | Say the importer looks specifically for folders named `barcodeNN`. |
| Why you would do this, "The HG002 long reads average Phred..." | I do not know how Phred 7.9 becomes one base in six. In class we only ever saw Q30 and were told it was good. I could not check the arithmetic or judge whether 7.9 is normal or a broken run. | Give the conversion once and say what Phred a good modern nanopore run reaches, so 7.9 has something to sit against. |
| Why you would do this, "still holds 950 reads covering the..." | Coverage was a word my class used without defining. 262 times sounds enormous and I could not tell whether that is a lot for nanopore or ordinary. | Gloss coverage as how many reads sit over an average position, and say what depth is enough for this kind of work. |
| Before you start, "Download the folder `ont-run` from the..." | Clicking into each folder, downloading the raw file, and rebuilding three levels of folders by hand is the step I was least confident about. I did not know what "raw file" means, and I was not sure whether my browser would rename or unzip the `.fastq.gz`. | A note that the file must stay compressed with its name unchanged, plus a way to check the rebuilt tree is right. |
| Before you start, "Importing a run folder needs no..." | I do not know what a plugin pack or Docker Desktop is. Being told I do not need them left me wondering whether I need them later, since demultiplexing is mentioned in the same breath. | Drop those two terms here or gloss them once, and say whether anything in this chapter needs them. |
| Procedure step 2, "Select the `fastq_pass` folder inside `ont-run`..." | This is the step I could not perform confidently. In the Mac open panel I did not know whether to highlight the folder and press Open, or go inside it first and press Open with nothing selected. Getting it wrong seemed likely to import nothing. | State that the folder should be highlighted, not opened into. |
| Procedure step 4, "Leave "Apply processing recipe after import"..." | The screenshot placed under this step shows Barcode Sheet controls that the step tells me to keep hidden. I looked for them on my sheet, could not find them, and took a while to work out that was expected. | A half sentence saying the pictured controls appear only once the checkbox is on. |
| Settings, "The first four settings below belong..." | I could not keep straight which settings live in which window. Two of the four have trailing colons in their names and the others do not, and the switch from the import sheet to the operations dialog happens mid list with nothing marking it. | Split Settings under two subheadings, one per window. |
| Settings, "The remaining settings belong to the..." | The FASTQ/FASTA Operations dialog is named here for the first time. The Procedure only told me to use a Tools menu item, so I did not know these were the same window. | Say in the Procedure that the Tools menu item opens that dialog. |
| Settings, "**(recipe picker).** Chooses which of the..." | A setting whose name is a description in brackets confused me. I did not know what to look for on screen. | Name it by where it appears, for example the popup under the checkbox. |
| Settings, "It starts on "Split by Fluidigm sample..." | The Fluidigm recipe needs a file with sample and barcode columns and the PacBio one needs three named columns, but I am not told what kind of file either is. The Barcode Source setting later describes a different file with different columns, and I could not tell these apart. | Say the file type for each and give a two line example. |
| Settings, "**Built-In Kit.** Names the commercial barcode..." | This is a trap I was warned about but could not avoid. My hypothetical kit came with a box label, not a string like `ont-nbd114`, and I would not know which entry to pick. | A line saying where the kit code appears on the kit box or in MinKNOW. |
| Settings, "Switch to Exact Bare Barcode when..." | I had to read this twice. Exact matching sounds stricter, but the sentence says to use it when positions are unpredictable, which sounded looser to me. | Separate the two ideas, freedom of position against strictness of sequence. |
| Settings, "**5' Distance.** Sets how many bases..." | The primes are never glossed in this chapter. My class said five prime out loud but I have never had to reason about which end of a read that is inside a file. | Gloss 5' and 3' at first use here, or link them to the glossary. |
| Settings, "**Error Rate.** Sets the fraction of..." | 0.15 times 20 is exactly 3, so I could not tell whether three mismatches is the limit or whether the number rounds and four would also pass. | Say whether the product is rounded down. |
| Settings, "**Output Strategy.** Chooses whether each selected..." | The caption for the Demultiplex Barcodes screenshot lists eight controls and Output Strategy is not among them, so I did not know where on screen to find it. | Add it to the caption, or say where in the dialog it sits. |
| Reading the results, "Click the new bundle in the..." | Nine summary cards and three sparkline charts is a promise I could not check, and I have not read the earlier chapter. I did not know which card mattered. | Name the two or three cards this chapter actually asks me to read. |
| Reading the results, "Input reads: 927" | The import found 950 reads and the demultiplex reports 927 going in. Nothing explains where the other 23 went, and I assumed I had done something wrong. | One sentence accounting for the difference. |
| Reading the results, "Assigned: 0 (0.0%)" | Showing a worked example that fails is honest, but I finished the chapter having never seen a successful demultiplex summary, so I would not recognise a good one. | Show a healthy summary next to the empty one. |
| Reading the results, "written as `unassigned.lungfishfastq` beside the per-barcode..." | I have not met that file type. I did not know whether it is a file or a folder, or how I would open it. | Gloss the bundle file extension once. |
| Reading the results, "Its manifest recorded an input read..." | I could not tell whether the Fluidigm manifest is the same `demux-manifest.json` named a paragraph earlier or a different file. | Name the file. |
| What good looks like, "and on this fixture it reported..." | A documented wrong number inside the software confused me. I could not tell whether this is a bug I should report, a known limitation, or something I caused. | Say plainly that the estimate is a known limitation. |
| On the command line, "lungfish-cli fastq scout Imports/HG002.chrM.ont.fastq.gz" | The Procedure said the import produces a bundle named `barcode01`, but the commands use a path named `HG002.chrM.ont.fastq.gz`. I could not reconcile the two names. | Use the name the Procedure produced, or say why it differs. |
| What this chapter does not cover, "POD5 and FAST5 files hold the..." | I did not know these existed, and for a moment I worried my fixture download was missing them. | Say these sit beside `fastq_pass` in a real run and are simply not needed here. |

One thing I learned. A nanopore read is one whole molecule, which is why the reads are so long, and the low per base accuracy is meant to be cancelled by stacking many reads over the same position rather than trusting any base on its own.

One thing I still could not do. Pick the right entry in Built-In Kit for a real library, because the chapter gives codes like `ont-nbd114` but never says where I would find that code for the kit on my bench.

The sentence I liked most. "You do not read individual nanopore bases as truth."
