# Fidelity review, 06-classification/04-running-taxtriage

Reviewed 2026-09-07 against the Swift source in this worktree, the CLI help
tree, `docs/user-manual/parameters.yaml`, and the author's own run outputs
under the chapter 35 scratch (`run-viral`, `run-batch`, and their SQLite
databases). The pipeline was not rerun. `lungfish-cli` was invoked read-only
once, to make a validation error reproduce.

The chapter is a large improvement on what DRIFT recorded, and the author's
central defect claim is correct in every link of its chain. The failures below
cluster in one place. The author established the run figures from the
pipeline's own `.odr.txt` report and the CLI, and then described the viewport
as if it showed those same figures. It does not. The viewport reads the SQLite
database that `build-db` wrote from the top-report fallback, which holds
fifteen rows rather than one, and a single-sample run shows a six-column table
rather than the nine-column batch table the chapter describes.

## Notes for the editor

Two things the review could not settle and one the author should carry forward.

The read-pair count is quoted twice with different values. The Why-you-would-do-this
section says 86,281 pairs and the Procedure says 83,591, and nothing in the chapter
reconciles them. The second figure is the one the runs used. The first is presumably
the SRA's deposited count before the fixture was trimmed, but no source read here
records it, so it stands as unverifiable rather than false.

The two aligned-read counts have the same problem. Reading the results quotes 163,031
from the pipeline's report and What good looks like quotes 165,500 from the SQLite
database, without saying they come from different files or why they differ. A reader
who cross-checks will think one of them is a typo.

The reporting-gap section is the chapter's best work and it is correct in every
particular. It would be stronger still if it said that the fallback also brings the
whole lineage into the table, since a reader expecting one row and finding fifteen
will assume the run went wrong rather than that the fallback is broader than the
report.
