## Consensus

Twenty-four rows were hit by three or more readers.

- Docker Desktop has no link, download location, or way to confirm it is running, and stops readers before the chapter starts.
- The trailing colon and full stop on every setting name reads as a typo.
- Max memory gives no way to check how much memory the reader's own Mac has.
- Extra arguments gives no plain statement that most readers should leave it empty.
- Depth is never glossed at its first use, though breadth is.
- The Required Setup pack and whether it needs any action from the reader is never stated plainly.
- Apple Containerization is named with no statement of whether it is automatic or needs action.
- The database size table never says what each named database, especially PlusPF, actually contains.
- The forty-character pipeline revision string is never explained as something the reader never types.
- The command-line prerequisite check is never marked optional for readers who have not opened a terminal.
- The read-pair count for the same sample differs across the chapter with no reconciliation.
- The alignment pane is named with no explanation of what it shows and no link to where it is documented.
- Abundance never states its unit or what it is a proportion of.
- The pipeline's own report file is never named or shown as reachable from inside the app.
- The aligned-read count in "What good looks like" disagrees with the count given earlier in "The reference run."
- Repetitive stretch is never glossed, so readers cannot picture why reads would pile onto one.
- Bundle is never glossed at its first use in the Procedure.
- Single-ended is never glossed even though paired-end is.
- Assembly is used in the step where the reader must choose before it is ever explained.
- K2 Confidence never states what its fraction is a fraction of, or names the broader group a demoted read is pushed into.
- The reported TASS score of 99 is never reconciled with the chapter's own 0 to 1 scale before it appears.
- Value-facet control is never glossed and readers cannot picture what it refers to.
- The amplicon-library exception to the unique-read rule is never stated, so readers cannot tell which rule applies to their own data.
- Amplicon library is never glossed at its first use, though the chapter leans on the term repeatedly later.
