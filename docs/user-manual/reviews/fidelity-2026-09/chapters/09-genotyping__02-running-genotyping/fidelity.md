## App defects

1. **`--min-support` / Min Reads is inert on a Genotype only run.** Confirmed at source, not just observed. `filter-demux-retained-bam.py` (`ONTBarcodeDemuxGenotypingPipeline+Scripts.swift:51`) declares the option and reads `args.min_support` only at lines 571 and 592, both of which write it into stats JSON. It is never a filter predicate. The only real consumer is `haplotypeDropoutEvaluator` (`ONTBarcodeDemuxGenotypingPipeline.swift:328-341`), reached at `:3611` and `:4365`, both inside haplotype-analysis paths that require a resolved definition set. A `genotypeOnly` run resolves none, so the value is carried and discarded. The CLI help promises otherwise: "Minimum retained unique-read support required for a genotype row in the report and workbook". The chapter documents the behaviour honestly. Author's finding, independently confirmed.

2. **A run whose `--output-dir` is spelled under `/private/tmp` fails at 84 percent, and the message names the wrong cause. The author's stated root cause is wrong.** The failure is real and reproducible (runs 3 and 4), and it does arrive after every expensive step. But it is not about world-writability and not about `/tmp` as a location. Run 5 wrote successfully into a `chmod 1777` directory under `$HOME`, and run 6 wrote successfully to `/tmp/fidtest2` while run 4 failed at `/private/tmp/fidtest`. The discriminator is how the path is spelled. `relativePath(from:to:)` (`GenotypeReviewableRowCatalogPublisher.swift:1277-1285`) guards `file.hasPrefix(prefix)` on two `standardizedFileURL.path` values, and `standardizedFileURL` rewrites `/private/tmp` to `/tmp` asymmetrically between the bundle URL and the output URL, so the prefix test fails and the code throws `outputOutsideBundle` on a path that is plainly inside the bundle. Two separate faults worth filing: the path-normalization mismatch itself, and `openOrCreateDirectory` (`:1805-1831`) reporting every `openat` failure as `outputOutsideBundle` regardless of errno, which is what makes the message misleading. **New relative to the author's report**, which attributed it to a hardened open under a mode-1777 directory.

3. **`fastq genotype-cohort` enforces an undocumented two-bundle minimum.** `FastqGenotypingSubcommand.swift:470` throws `"At least two input FASTQ bundles are required for genotype-cohort."`, but the CLI help for the subcommand says only that each input must be a bundle holding one prepared per-sample FASTQ. A user genotyping a single sample gets a late validation error with no help-text warning. **New.** This also corrects DRIFT row 2.23, which told the rewriter to "Drop the two-bundle minimum" as though it were a false claim. It is real.

4. **Reality-map correction, carried forward.** The map's "Missing from this chapter" table lists `Savont Clustering` as a `Tools > Genotyping` item. It is not. `FASTQOperationDialogState.toolIDs(for:)` at `:1282-1287` puts `.savont` and `.pbaa` under `.clustering`, and `.genotyping` returns only `[.ontGenotyping]`, to which the menu builder appends the two workflow-library entries. The chapter was right to ignore the row. Author's finding, confirmed.
