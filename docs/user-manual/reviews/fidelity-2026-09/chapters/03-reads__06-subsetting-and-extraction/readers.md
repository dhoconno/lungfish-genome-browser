## Consensus

Thirty-one rows were hit by three or more readers.

- A bundle's folder-versus-file nature and its `.lungfishfastq` extension are never pinned down for a reader who has not seen one before.
- The fixture is called "45,574 read pairs" in one place and treated as a plain read count everywhere else, so no arithmetic checks out cleanly.
- Five sequencing runs are named but the results only ever split reads by two instruments, and the second instrument is never named at all.
- Docker Desktop is mentioned with no explanation and reads as a warning rather than a reassurance.
- Depth is used with no gloss anywhere in the chapter.
- Per Input is asserted as the right choice before its meaning is explained, many paragraphs later in Settings.
- The dialog is described by what it lacks, such as a wizard, rather than by what it actually looks like, and its name shifts between pane and window.
- 0.15 times a 16-base overlap equals 2.4, and the chapter never says whether that rounds down.
- 260 plus 261 equals 521, and the chapter never says whether a read matching both halves is counted once or twice.
- Min Overlap's claim about "reads this long" depends on a read length the chapter does not state until much later.
- Keep Matched Reads packs the window default, the command-line default, and a plain "off" into a single confusing sentence.
- The only way to get a plain FASTQ file out of a subset bundle is a terminal command, which a chapter calling the command line optional never resolves for a reader with no terminal.
- The sentence "asking for 10,000 reads gives you 5,000 pairs, which is 10,000 reads" reads as circular no matter how many times it is reread.
- The term "name line" is used well before any real FASTQ header is shown as an example.
- Readers cannot tell what makes typed text look like a file path, so LGE's automatic choice between sequence and path feels unpredictable.
- 5 prime and 3 prime are taught as chemistry, not as directions inside a read as written in a file, and the chapter never bridges the two.
- The bracket example is the only pattern syntax shown, leaving readers unsure whether IUPAC codes work or what else the regular-expression checkbox changes.
- A command-line comparison is dropped into the middle of the Search End window setting, breaking the reader's sense of which surface they are reading.
- The command line's `right` value for search end is never mapped back to the window's 3' End label.
- Four extraction routes are named in one closing sentence, with three of them never explained on the page.
- "Within a percent or so" is too vague a tolerance for a chapter otherwise built on exact numbers.
- No rule is given for choosing a Min Overlap value on data other than this one fixture, only that 8 was bad and 16 worked here.
- Edit distance and the Java error at the end of the command-line section are both left unglossed.
- Gzip-compressed is never explained, leaving readers unsure whether the file can still be opened afterward.
- The two imported files are merged into one interleaved file with no plain statement that this has happened, and interleaved and consecutive records are both new terms.
- Readers reaching the GitHub download page cannot tell whether to click each file or the folder.
- The warning "read the next paragraph before using" gives its own content nowhere, leaving readers anxious about whether a wrong query is harmful.
- The unnamed second instrument recurs as a problem again at the results and verification stage, not only where it is first introduced.
- Alu right-arm end appears as a brand-new term at the very end of a results paragraph with no gloss.
- Readers are alarmed that a subset bundle holds no reads of its own, unsure whether it survives being copied or shared.
- The step introducing the Count field packs an empty field, a disabled button, and its hint message into one dense, twice-read sentence.
