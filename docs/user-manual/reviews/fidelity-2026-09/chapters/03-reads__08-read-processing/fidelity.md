## Notes for the author

Two of the five false verdicts (rows 10 and 28) are the same underlying
error, and row 34 is its downstream consequence. The HG002 chr20 reads were
quality-trimmed before they were deposited, so "2x250" describes the
instrument configuration rather than the reads on disk. Fixing row 10 fixes
the premise that rows 28 and 34 lean on.

Row 21 is the only claim that would send a reader looking for a folder that
is not there. The bundle suffix comes from the derivative request's kind
string, not from the menu title, so the six suffixes are `pairedEndMerge`,
`pairedEndRepair`, `reverseComplement`, `translate`, `orient`, and
`errorCorrection`.

Row 48 is a case where the chapter is right and DRIFT is wrong. The DRIFT
"Missing" row cites `FASTQOperationDialogState.swift:2200-2210` for the
claim that only Reverse Complement and Translate offer Output Strategy, but
those lines are `supportsFASTA`. The picker is gated by
`supportsConfigurableOutput` at `:2135-2141`, which admits all six. The
chapter documenting Output Strategy on every operation is correct, and the
DRIFT row should be struck rather than followed.

Both defect claims reproduce on the shipped binary and neither is documented
as behaviour in the chapter, which is the right call for the interleave one
and a judgement call for the orient one. The chapter's instruction to
compare the orient output count to the input count every time is the only
protection a reader currently has against the silent empty output.
