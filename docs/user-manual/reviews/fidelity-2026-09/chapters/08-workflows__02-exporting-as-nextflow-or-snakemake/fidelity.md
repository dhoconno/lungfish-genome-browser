## App defects

The chapter reports four. All four reproduce independently on a fresh export.
My assessment of each, on the question the review was asked to settle, whether
it is a real emitter bug or a limitation the chapter should frame differently.

**1. Nextflow workflow block calls a three-input process with one channel.
Real bug.** `main.nf:29-32` declares three `path` inputs on `MINIMAP2_1`, and
`main.nf:121` calls it with one. The emitter declares one channel per recorded
input file (`main.nf:113-119`) and then wires processes in a linear chain by
output, so every channel after the first is orphaned. Ten of the eleven lint
warnings are the symptom, five "Variable was declared but not used" plus the
deprecated `Channel` spelling. This is not a limitation of recorded provenance,
since the record holds all three inputs correctly and the process declaration
proves it. The workflow-block generator is simply not using them. The chapter
frames it correctly as an exporter defect.

**2. Snakemake `samtools_5` lists the same BAM as input and output. Real bug,
and the framing could be sharper.** `Snakefile:70-76`. The underlying cause is
that `samtools flagstat` reads a BAM and writes nothing to disk, so the recorded
step has an input but no true output, and the emitter appears to have filled the
output block from the step's declared artifacts rather than from files the
command creates. `main.nf:99-104` has the identical shape, listing
`HG002.sorted.bam` as both input and output of `SAMTOOLS_5`, so this is one bug
surfacing in two emitters, and Nextflow simply does not fail on it the way
Snakemake's DAG builder does. The chapter attributes it to "the recorded
`samtools flagstat` step lists…", which reads as though the provenance record is
at fault. The record is fine. Suggested reframing: "the emitter gives the
`samtools flagstat` rule the same BAM as both input and output, because flagstat
reads a file and writes only to standard output, so the rule appears to depend
on itself."

**3. Duplicated parameter keys. Real bug.** Four sites, one more than the
chapter counts: `main.nf:18-19` (params), `main.nf:118-119` (workflow channels),
`config.yaml:7-8`, and `reproduce.py:24-25`. The chapter names three of the four
and omits the workflow-block pair, though it is visible in the lint output it
already quotes. Cause is confirmed as the chapter says, two recorded steps
(`samtools index` and `samtools flagstat`) both declare `HG002.sorted.bam` as an
input and nothing deduplicates. Worth noting the Python case is the most harmful
of the four, since a duplicate key in a Python dict literal is silently discarded
rather than merely redundant.

**4. Absolute host paths in every emitted command. Real, but it is a limitation
the chapter should keep framing as it does.** This one differs in kind from the
other three. The recorded provenance genuinely contains absolute paths, because
that is what ran, and the export's stated purpose is to be a faithful record.
Rewriting them into `${params.x}` references would be a design change, not a bug
fix. The chapter's framing is already right, calling the declared parameters and
channels "decorative on any second machine" in the author record and, in the
chapter itself, saying the commands "will not resolve elsewhere" while listing it
alongside the other three as an exporter defect. I would keep it grouped with the
others for the reader's purposes, since the practical consequence is identical,
but the editor should know that defects 1, 2, and 3 are fixable in the emitter
without any design decision, and defect 4 is not.
