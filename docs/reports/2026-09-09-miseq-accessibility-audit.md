# miSeq accessibility audit — 2026-09-09

This is a source and test-coverage review, not a claim of accessibility certification or completed user testing. No scientific data or production code changed. Line numbers refer to the working tree reviewed today.

## Highest priorities

1. **P1 — Make haplotype assignments readable without decoding color.** `Sources/LungfishGenotypeUI/GenotypeHaplotypeTapeView.swift:175` fills assigned reference/manual bars but does not draw the associated name. The accessibility buttons do narrate sample, locus, H1/H2, value, status and source (`:404`), which is good for VoiceOver but does not help a sighted analyst with low vision or impaired color discrimination. Add a persistent, scalable haplotype name in each slot, with contrast-selected foreground, plus an optional dense mode for experienced analysts. Keep tooltips/evidence details as supplementary explanations. Do not equate distinct colors with sufficient distinguishability.

2. **P1 — Scale the actual H1/H2 target, not just row text.** `GenotypeOutlineView.swift:451` fixes the tape at 26 pt despite scalable table rows (`:496`). `GenotypeHaplotypeTapeView.swift:397` divides that into two 13 pt-high clickable targets. Its error/observed/unavailable glyphs cap at 10–11 pt and permit 7 pt (`:235`, `:249`, `:263`). Larger text therefore does not enlarge the critical target or glyph. Derive tape height and glyph font from shared ContentTypography; offer a comfortable density with a practical 24 pt minimum per slot, then validate target acquisition with staff. A specific target size is a design recommendation here, not a measured compliance finding.

3. **P2 — Complete text-size coverage around the shared reference list.** The actual embedded reference record table inherits typography-aware `BatchTableView` (`Sources/LungfishApp/Views/Results/Reference/ReferenceBundleRecordTable.swift:37`, `:88`). However the enclosing `MHCReferenceBundleViewport.swift:169–305` uses fixed SwiftUI headline/caption styles without a ContentTypography model, and its mode selector is fixed at 210 pt (`:183`). The reference summary label also uses `smallSystemFontSize` (`ReferenceBundleViewportController.swift:101`). Connect these surrounding elements to the same app preference and verify narrow-window/large-text layouts. Avoid incorrectly replacing the already shared table merely because the surrounding shell is inconsistent.

4. **P2 — Verify small action controls at large text.** Evidence Change, section menu and review controls explicitly use `.controlSize(.small)` (`GenotypeCallEvidenceView.swift:841`, `:924`, `:1330`); other result actions use AppKit `.small` (`GenotypeResultViewController.swift:5684`, `:5829`, `:9667`). Evidence typography itself is shared and tested. Inspect actual rendered control bounds/focus rings at maximum text size before changing all controls globally. Prefer normal-sized primary actions, small secondary actions only when the surrounding hit area remains comfortable.

5. **P2 — Test workflow setup typography alongside results.** The miSeq run pane exposes report/analysis names, Threads and Min Reads with existing help (`Sources/LungfishApp/Views/FASTQ/FASTQOperationToolPanes.swift:553–562`). It uses the broader shared FASTQ form machinery and contains a technical persistent helper. Its source does not directly consume ContentTypography; verify whether the host applies an equivalent scale, then align behavior if absent. The MHC shell and run form should respond to the same Larger command that analysts use in the matrix.

## Strengths worth preserving

- App-wide **View → Content Text Size → Larger/Smaller/Default**, with Command-Option shortcuts, exists (`Sources/LungfishApp/App/MainMenu.swift:493–537`). Shared typography has a 10 pt floor (`Sources/LungfishKit/ContentTypography.swift:130`) and scales table rows. This is distinct from genomic coordinate zoom.
- Matrix typography scales pinned and scrolling rows together (`GenotypeComparisonMatrixView.swift:5624`); outline text/row height also responds (`GenotypeOutlineView.swift:496`). Sequence detail fonts scale too (`GenotypeAlleleSequenceDetailView.swift:181`).
- Matrix foreground selection computes luminance after background alpha compositing and chooses black or white for automatic text (`GenotypeComparisonMatrixView.swift:6136–6185`). Explicit analyst text-color overrides bypass this automatic choice (`:6140`); offer a warning or automatic readable-color reset if testing finds unreadable custom combinations, rather than silently rewriting analyst annotations.
- Matrix Increase Contrast behavior and semantic cell accessibility exist (`GenotypeComparisonMatrixView.swift:4979–5005`, `:5072`). Row/column selectors are native accessible controls with labels/value descriptions and stable identifiers (`:6561–6586`, `:6835–6850`).
- Haplotype targets are actual focusable native buttons, support Space/Return and accessibility press, and draw a keyboard focus ring (`GenotypeHaplotypeTapeView.swift:495–526`). Names are available to assistive technology even though absent visually.
- Existing tests cover evidence and sample-sheet typography, matrix manual-band typography, numeric-control accessibility, and effective haplotype keyboard/AX activation. Examples: `GenotypeCallEvidenceViewTests.testContentTypographyModelUpdatesEvidenceMetricsWithoutChangingEvidenceOrActions`, `GenotypeHaplotypeCallBandTests.testEffectiveTargetsSupportClickKeyboardAndAccessibilityPress`, `GenotypeManualHaplotypeAccessibilityTests`, and `GenotypeNumericFilterControlTests`. These are valuable regression checks, not substitutes for assistive-technology testing.

## Validation to perform before declaring the workflow accessible

Use the complete miSeq reference and a representative five-sample result, a narrow window, and a wider lab display. At default and maximum text size, complete: choose input/reference; run; inspect failure/success; compare haplotype/genotype; filter diagnostic alleles; inspect supporting reads; copy/extract reference sequences; stage/cancel/apply an override; update/export workbook. Repeat with keyboard only, VoiceOver, macOS Increase Contrast and both appearances. Confirm no clipped names, hidden primary buttons, lost keyboard focus after filtering/refresh, or distinction conveyed only by color. Include staff with low vision in target-acquisition and readability testing; ask them to find an allele, explain its supporting call, and safely cancel an override. Measure observed errors and completion, rather than relying on visual preference alone.

## Coverage and limits

Read the haplotype tape/outline, genotype matrix typography/contrast/accessibility, evidence and override-adjacent controls, shared reference table and MHC reference shell, sequence-detail typography, miSeq run-pane fields, global text-size command, and representative test coverage. No live VoiceOver session, screen contrast measurement, actual staff study, or entire run execution was performed in this bounded audit. Other team members cover information architecture, terminology and contextual help. Findings marked verified above derive directly from source; proposed dimensions and predicted low-vision difficulty require live validation.
